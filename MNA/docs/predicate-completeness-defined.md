# Predicate Completeness — Formal Definition

## Status

This document freezes the foundational definition for:

```
Stage 4 — Predicate Completeness / Independency Testing
```

This stage exists to determine:

```
whether a predicate-anchor environment forms
a structurally complete predication
```

This document is foundational because:

- true trunk extraction depends on it,
- `[S]` and `[M]` depend on it,
- connector relationships depend on it,
- labels, patterns, units, and titles ultimately depend on it.

No implementation should proceed until these definitions are frozen.

------

# Core Governing Principle

```
Independent clauses are determined by predicate completeness,
not by connectors.
```

And:

```
Connectors may contribute evidence,
but they do not govern independency.
```

This distinction is non-negotiable.

------

# Purpose Of Stage 4

Stage 4 exists to determine:

```
whether a predicate-anchor environment
is structurally complete or structurally dependent
```

This stage is the first true structural layer in MNA.

However, it must remain:

- mechanical,
- conservative,
- auditable,
- reproducible,
- minimally interpretive.

------

# Predicate Anchor Reminder

A predicate anchor is:

```
one verified finite verb inherited from Stage 1
```

A predicate anchor alone is NOT:

- an independent clause,
- a trunk clause,
- a section,
- a unit,
- a title,
- a discourse boundary.

A predicate anchor is only:

```
finite-clause center candidate
```

------

# Predicate Environment

Stage 4 does not evaluate isolated finite verbs.

Stage 4 evaluates:

```
predicate-anchor environments
```

Meaning:

```
the local grammatical environment
surrounding a predicate anchor
```

This environment may include:

- required complements,
- infinitival environments,
- relative structures,
- participial structures,
- conditional environments,
- subordinate structures,
- ellipsis environments,
- quoted structures,
- conjunction contribution,
- dependency indicators.

------

# Predicate Completeness

## Working Definition

A predicate-anchor environment is predicate-complete when:

```
it forms a structurally complete predication
without requiring structural completion
from another predicate-anchor environment
```

------

# Independent Predicate Environment

An independent predicate environment:

```
can structurally stand
as a complete predication
```

even if:

- expanded,
- modified,
- supplemented,
- qualified,
- connected,
- or coordinated.

Structural expansion does not automatically remove independency.

------

# Dependent Predicate Environment

A dependent predicate environment:

```
requires structural completion
from another predicate-anchor environment
```

Examples may include:

- subordinate clauses,
- relative clauses,
- purpose clauses,
- result clauses,
- explanatory dependencies,
- infinitival dependency structures,
- conditional dependencies.

These examples must not become semantic assumptions.
 They remain grammatical dependency environments only.

------

# Critical Constraint

```
Dependency must not be determined
by connectors alone.
```

Because:

- connectors may be omitted,
- connectors may be ambiguous,
- connectors may perform multiple functions,
- dependency may exist without explicit connectors,
- independent clauses may contain connectors.

Therefore:

```
predicate completeness governs independency
```

not connector presence.

------

# Mechanical Priority Order

Stage 4 must evaluate in this order:

```
1. predicate completeness
2. dependency environment
3. connector contribution
```

NOT:

```
1. connector
2. assumed dependency
3. predicate
```

This ordering is architecturally critical.

------

# What Stage 4 May Use

Allowed:

- predicate anchors,
- local grammatical environment,
- morphology,
- structural dependency indicators,
- infinitival structures,
- relative structures,
- participial structures,
- conjunction contribution,
- structural incompleteness indicators.

------

# What Stage 4 May NOT Use

Forbidden:

- theology,
- semantic interpretation,
- discourse assumptions,
- thematic flow,
- commentary tradition,
- paragraphing,
- translation punctuation,
- inferred author intent,
- section headings,
- labels,
- units,
- titles.

------

# Stage 4 Does NOT Yet Produce

Stage 4 does NOT yet create:

- trunk,
- `[S]`,
- `[M]`,
- connector networks,
- labels,
- patterns,
- units,
- titles.

Stage 4 ONLY determines:

```
predicate completeness status
```

------

# Possible Output States

Conservative classifications may include:

```
INDEPENDENT
DEPENDENT
UNCERTAIN
```

The system must prefer:

```
UNCERTAIN
```

over:

- forced interpretation,
- semantic guessing,
- artificial certainty,
- connector-driven assumptions.

------

# Anti-Drift Rules

Stage 4 must never:

- force completeness from semantics,
- force dependency from connectors alone,
- silently reinterpret lower layers,
- collapse uncertainty into certainty,
- treat coordination as dependency automatically,
- treat connector presence as independency loss automatically.

------

# Relationship To Later Stages

Stage 4 enables:

```
Stage 5 — true trunk extraction
```

Because:

```
true trunk
=
independent predicate-complete environments only
```

Only AFTER trunk extraction may:

- Stage 6 calculate `[S]`,
- Stage 6 calculate `[M]`,
- Stage 7 analyze connector relationships,
- Stage 8 determine labels/patterns/units,
- Stage 9 generate titles.

------

# Final Freeze Statement

The MNA system must never:

- allow connectors to generate independency,
- collapse finite verbs into independent clauses,
- collapse predicate anchors into trunk,
- calculate trunk-only markers before trunk extraction,
- imply certainty beyond mechanical verification.

Every layer must remain:

- explicit,
- auditable,
- reproducible,
- mechanically constrained,
- and structurally conservative.
