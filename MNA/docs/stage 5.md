# Stage 5 — Proposed Mechanical Definition

## Working Definition

```
Stage 5 extracts stable surviving trunk structures
from Stage 4 audited clause relationships,
using explicit survival rules,
without semantic prioritization.
```

This is clean and safe.

------

# What Stage 5 Is NOT

Stage 5 is NOT:

- main ideas,
- author emphasis,
- theological center,
- rhetorical climax,
- discourse prominence,
- semantic compression.

Ban these completely from Stage 5 vocabulary.

------

# Stage 5 Input

Consumes:

```
Stage 4 audited structures
```

including:

- clause IDs,
- dependency classifications,
- connector metadata,
- preserved conditional units,
- subject continuity,
- warnings,
- flags.

------

# Stage 5 Output

Produces:

```
stable trunk survivals
```

NOT:

```
interpretive summaries.
```

------

# Most Important Architectural Shift

Stage 4 asked:

```
Can this clause stand independently?
```

Stage 5 asks:

```
Does this survive in the trunk structure?
```

Those are different.

A clause may:

- fail independency,
- yet survive structurally.

You already proved this with:

```
εἰ / ἐὰν
```

------

# Stage 5 Core Principle

The trunk is:

```
a surviving structural backbone
```

NOT:

```
a hierarchy of importance.
```

------

# Likely Stage 5 Rule Categories

You probably now need:

```
roots_survival_rules.yaml
```

distinct from dependency rules.

------

# Possible Survival Rule Types

## 1. Preserve-As-Unit

Example:

```
conditional pairs
```

Meaning:

```
protasis + apodosis survive together
```

------

## 2. Remove-Safely

Example:

```
fully detachable subordinate expansions
```

provided no survival rule protects them.

------

## 3. Preserve-Chain

Example:

```
finite clause continuity chains
```

------

## 4. Preserve-Coordinated Continuity

Example:

```
καὶ / δέ linked survivals
```

where structurally inseparable.

------

# Important Warning

Do NOT create:

```
“main clause” rules.
```

That terminology is dangerous because humans automatically reinterpret:

```
main
```

semantically.

Prefer:

```
surviving structure
stable trunk unit
preserved unit
structural backbone
```

These are safer.

------

# Strong Recommendation

Stage 5 should probably remain:

```
loss-minimizing
```

rather than:

```
aggressively reductive.
```

Meaning:

when uncertain:

```
preserve
rather than destroy.
```

Because false deletion is far more damaging than temporary over-preservation.

Especially at this stage.

------

# Important Future Insight

Stage 6 may later reveal:

```
survival inconsistencies
```

that refine Stage 5 backward.

That is healthy.

So Stage 5 should remain:

```
structurally conservative
```

until downstream stages stabilize.

------

# The Most Important Rule Going Forward

This should probably govern all Stage 5 work:

```
A structure survives because of explicit mechanical survival rules,
not because reviewers perceive it as important.
```

That sentence protects the project from drifting into commentary systems.
