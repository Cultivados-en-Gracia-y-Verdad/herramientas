# Developmental Process View

## 1. Purpose

The developmental view must show the observation process, not merely the conclusion.

The goal is not to tell the student what the section means.

The goal is to help the student see how developmental pressure appears, continues, interrupts, resumes, intensifies, or closes in the text.

## 2. Core Principle

The view should expose the path of observation.

Not just:

- Signal detected.
- Contrast exists.
- Development continues.

But:

- Where did the signal first appear?
- Where did it repeat?
- Where did it appear to pause?
- Where did it resume?
- Where did it intensify?
- Where might it close?

## 3. What the View Must Show

For each developmental signal, the view should show:

1. First appearance
2. Repeated appearances
3. Current unresolved span
4. Interruptions or pauses
5. Re-entry / resumption points
6. Escalation points if visible
7. Possible closure points if visible
8. Review status

## 4. What the View Must Avoid

The view must not present observations as final interpretation.

Avoid:

- final H1/H2 conclusions,
- sermon-like titles,
- theological synthesis,
- abstract labels detached from the text,
- unexplained scores,
- dense metrics,
- hidden reasoning.

## 5. Preferred Display Pattern

The view should be process-oriented:

```text
SIGNAL: falta / completo

1:2-4  first pressure appears
       trials -> perseverance -> complete -> lacking nothing

1:5-8  pressure continues
       lack of wisdom + instability/doubt

status: unresolved / review
question: Is the lack/completion pressure still active?
```

## 6. Student Training Purpose

The view should train students to ask:

- What appeared first?
- What returned?
- What remained unresolved?
- What interrupted the development?
- Did the earlier pressure resume?
- Did the pressure close or shift?

## 7. Evaluation Standard

A developmental view succeeds if a student can follow the visible path of the signal through the text.

It fails if the student only sees a conclusion without understanding how the observation was reached.

## 8. Implementation Direction

The first renderer should therefore produce a process trace, not a conclusion report.

For each signal, it should output:

- signal label,
- observation question,
- verse-by-verse hits,
- side A / side B matches,
- unresolved span,
- review notes,
- no final structural conclusion.
